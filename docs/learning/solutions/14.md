# Solutions · 14 Cloud concepts (theoretical)

## Exercises
1. ```sql
   MERGE dataset.fact_transactions f
   USING (SELECT ... FROM dataset.stg_transactions s JOIN ... ) s
   ON f.transaction_id = s.transaction_id
   WHEN MATCHED AND s.batch_id >= f.batch_id THEN UPDATE SET status = s.status, ...
   WHEN NOT MATCHED THEN INSERT (...) VALUES (...);
   ```
   Surrogate keys from hashes (`FARM_FINGERPRINT(customer_id || valid_from)`) instead of sequences.
2. Pipeline SA: Storage Object Creator/Viewer on the lake bucket, BigQuery Data Editor on the
   warehouse dataset, Job User. Airflow SA: permission to run Cloud Run Jobs as the pipeline SA.
   Analyst: Data Viewer on marts (+ Job User). Dashboard SA: Data Viewer on the marts dataset only.
3. Unpartitioned: the scan reads the referenced columns for all rows (e.g. 3 columns × 8 bytes ×
   1e9 ≈ 24 GB). Partitioned by day with a one-day filter: roughly 1/N of that for N days of data.

## Interview answers
1. Lake → GCS, warehouse → BigQuery (MERGE, partitioning, clustering), orchestration →
   Composer, steps → Cloud Run Jobs, secrets → Secret Manager, identities → service accounts.
2. Partitioning splits storage by a column (pruned by filters); clustering sorts within
   partitions to skip blocks.
3. Partition filters, clustering, selecting only needed columns, materialising marts,
   quotas/reservations.
4. Workload identity/attached service accounts with least privilege; no long-lived keys.
