# Solutions · 12 Testing data pipelines

## Exercises
1. ```python
   def test_lower_case_currency_is_normalised(ctx, valid_transaction):
       result = run([{**valid_transaction, "currency_code": "usd", "amount": "1.00"}], ctx)
       assert result.accepted.iloc[0]["currency_code"] == "USD"
   ```
2. ```python
   from hypothesis import given, strategies as st
   @given(st.decimals(min_value=0, max_value=10**9, places=2))
   def test_round_trip(value):
       minor = parse_amount_minor(pd.Series([str(value)])).iloc[0]
       assert format_minor(int(minor)) == f"{value:.2f}"
   ```
3. With `keep="last"`, the *copy* is kept and the first occurrence marked duplicate. Counts stay
   equal, so most tests pass; `test_valid_record_wins_over_invalid_duplicate_key` still passes.
   Add a test asserting the quarantined duplicate is at `record_position` 1, not 0.
4. Build `QualityConfig(max_reject_rate=0.01, ...)` (or monkeypatch the TOML path) and assert
   `QualityGateError` on the default 5% error rate.

## Interview answers
1. Unit tests for rules, contract tests for schemas, integration tests for guarantees
   (idempotency, reconciliation, recovery), data tests in production (quality rules).
2. Unit: one function, tiny fixtures. Integration: real storage/DB, whole flow. Contract: shapes
   and types at boundaries.
3. Run twice, compare counts and sums (and keys) before and after.
4. Small deterministic data, temporary directories/databases, in-process services, opt-in
   markers for slow suites.
