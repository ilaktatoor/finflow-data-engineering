# Solutions · 06 ETL pipelines

## Exercises
1. Add `maybe_fail("transform")` after `_write_quality_report` and before `_write_silver` in
   `transform`. State: batch `FAILED`, quality report and quarantine written, no Silver files.
   A rerun recomputes everything from Bronze and overwrites the report: it recovers.
2. Wrap the enrichment in `transform` with `track_step(rt, ETL, "enrich", batch.batch_id)` and
   set `m.records_out = int(result.accepted["is_late_arriving"].sum())`. Note that `track_step`
   writes outside the load transaction — acceptable for metadata.
3. The simulated failure now happens after commit: data and watermarks are committed but the
   batch is marked `FAILED`. A rerun is still safe (idempotent upserts) — which is exactly why
   idempotency matters — but status and reality disagree.
4. `backfill` runs `run_etl(..., force=True)`; `ingest` finds the batch marker and replays Bronze
   without touching `data/landing`.

## Interview answers
1. Deterministic outputs per input, natural-key upserts or partition overwrites, write-once raw
   data, state changes (watermarks) committed with the data.
2. Replay after bugs, audit ("what exactly did we receive?"), and reprocessing without the source.
3. In FinFlow nothing: dimensions and facts are in one transaction, so the rollback undoes both.
   Without that, facts would later fail to find dimensions or reconcile.
4. `finflow backfill --start D --end D` (or the reprocess DAG): replays from Bronze.
