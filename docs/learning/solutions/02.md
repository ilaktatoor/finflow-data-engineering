## Exercises
1. ```python
   def apply_rows() -> pd.Series:
       return df.apply(lambda r: int((Decimal(int(r.amount_minor)) * int(r.rate_micros) / 10**6)
                                     .quantize(Decimal("1"), ROUND_HALF_UP)), axis=1)
   ```
   Expect it close to `iterrows` (same per-row Python work, slightly less overhead), far from
   the vectorised version.
2. ```python
   silver = pd.read_parquet("data/lake/silver/transactions")
   silver.pivot_table(index="txn_date", columns="status", values="transaction_id", aggfunc="count", fill_value=0)
   ```
3. One bad timestamp raises inside `transform_entity`; the whole batch fails and no record is
   quarantined. Coercing to `NaT` and recording `invalid_format:event_ts` isolates the record and
   keeps the evidence.
4. In `_business_checks("transactions")` add
   `pa.Check(lambda df: (df["channel"] != "ATM") | df["transaction_type"].isin(["WITHDRAWAL", "DEPOSIT"]), name="atm_channel_type", ignore_na=False)`
   and a parametrised case in `test_invalid_records_are_quarantined_with_reason` with
   `{"channel": "ATM"}` (the fixture is a PURCHASE) expecting `business:atm_channel_type`.
   Mirror it in the ELT SQL or reconciliation will (correctly) fail.

## Interview answers
1. Each row becomes a Python object and runs interpreted code; vectorised operations run once
   per column in C. Use column expressions, `np.where`, `merge`, `groupby` aggregations.
2. Nullable `Int64` (or Arrow-backed integers): missing values are `<NA>`, not `NaN` floats.
3. The right side had duplicate keys (many-to-one assumed, many-to-many happened). Check with
   `validate="many_to_one"` in `merge`.
4. Read in chunks (`chunksize`) and aggregate incrementally, read only needed columns with
   proper dtypes, convert to Parquet once, or use an out-of-core engine (DuckDB, Polars lazy).
