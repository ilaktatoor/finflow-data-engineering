# Solutions · 15 Interview preparation

1. **Streaming card transactions**: an event log (Pub/Sub, Kafka) instead of files; idempotent
   consumers keyed on `transaction_id`; micro-batches or a stream processor; watermarks become
   event-time watermarks with allowed lateness; the quality gate becomes per-window metrics and
   dead-letter queues instead of batch rejection.
2. **3% drop**: check freshness and batch status first (was a batch late or gated?), then
   rejection rates per rule, then compare raw input counts (Bronze manifests) with yesterday,
   then segment the drop (channel, currency, merchant) before calling it a business change.
3. **Amounts in cents**: the amount distribution shifts ×100; `HIGH_AMOUNT` flags would spike,
   and an anomaly rule on daily totals would fire. Today FinFlow has no distribution check —
   a good addition (mean/percentile drift per batch).
4. **"Total processed value"**: write the definition down (statuses included? gross or
   completed? currency conversion date?), implement it once in a mart, and reconcile other
   numbers to it.
5. **Backfill a year**: fix, test on one day, then replay batches from Bronze in order with
   limited parallelism; compare counts/sums before and after; refresh marts; communicate.
