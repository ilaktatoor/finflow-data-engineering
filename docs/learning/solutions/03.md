# Solutions · 03 SQL fundamentals

## Exercises
1. Put the condition in the `ON` clause:
   ```sql
   SELECT a.account_id FROM dim_account a
   LEFT JOIN fact_transactions f ON f.account_key = a.account_key AND f.status = 'COMPLETED'
   WHERE f.transaction_id IS NULL;
   ```
2. ```sql
   SELECT m.category, COUNT(DISTINCT c.customer_id) AS customers,
          SUM(f.amount_mxn_minor) / COUNT(*) / 100.0 AS avg_ticket_mxn
   FROM fact_transactions f
   JOIN dim_merchant m ON m.merchant_key = f.merchant_key
   JOIN dim_customer c ON c.customer_key = f.customer_key
   GROUP BY m.category ORDER BY customers DESC;
   ```
   `COUNT(DISTINCT c.customer_id)`, not `customer_key`: one customer can have several versions.
3. ```sql
   WITH type_avg AS (SELECT transaction_type_key, AVG(amount_mxn_minor) AS avg_minor
                     FROM fact_transactions GROUP BY 1)
   SELECT f.transaction_id, f.amount_mxn_minor FROM fact_transactions f
   JOIN type_avg t USING (transaction_type_key) WHERE f.amount_mxn_minor > t.avg_minor;
   ```
   Both engines usually produce the same plan (decorrelation); the CTE is clearer.
4. Each fact matches *every* version of its customer: customers with 2 versions are counted
   twice. The surrogate key identifies exactly one version.

## Interview answers
1. WHERE filters rows before grouping; HAVING filters groups after aggregation.
2. `GROUP BY ... HAVING COUNT(*) > 30`, or a CTE with the counts filtered in an outer `WHERE`.
3. When a condition on the right-hand table is in `WHERE` (NULLs fail it).
4. `COUNT(DISTINCT)` needs a hash set or sort of the values; `COUNT(x)` just counts non-nulls.
